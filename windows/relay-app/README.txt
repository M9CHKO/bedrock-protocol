CPE RELAY — WINDOWS x64  /  1.0.2

ЗАПУСК
Запустите CPE-Relay-Windows-1.0.2-x64.exe. Можно передать другому человеку
только этот EXE: DLL, данные обеих версий, .NET и лицензии находятся внутри.
При первом запуске .NET автоматически распакует служебные файлы в свой
локальный кэш (%TEMP%\.net). ZIP-архив и ручная распаковка не нужны.
Настройки и токены каждого пользователя создаются отдельно и не входят в EXE.
Устанавливать .NET отдельно не нужно. Требуется Windows 10/11 x64.

1. В «Подключение» выберите версию установленного Minecraft Bedrock,
   введите адрес и порт нужного сервера. Нажмите «Запустить реле».
2. В Minecraft добавьте сервер: 127.0.0.1, порт 19132.
3. При первом входе в окне реле появится код Microsoft.
   Нажмите «Открыть страницу входа» и завершите вход на сайте Microsoft.
   Пароль вводится только на сайте, не в реле. Коды не пишутся в журнал.
4. Для выхода остановите реле или закройте приложение.
   Окно и плавающая панель при закрытии скрываются сразу. Ядро работает
   в отдельном скрытом процессе; если оно не отвечает на остановку за
   3 секунды, завершается только этот процесс. Minecraft не закрывается.
   Можно остановить даже незавершённый запуск или ожидание авторизации.

ПРОФИЛИ И ТОКЕНЫ ПО НИКУ
В разделе «Профили» укажите ник/название локального профиля до запуска.
После входа токены автоматически сохраняются в
%LOCALAPPDATA%\CPE Relay Windows\profiles\ИМЯ\auth.
Выберите сохранённый профиль в списке, чтобы использовать его снова.
Название профиля не меняет ник Minecraft и не подменяет личность аккаунта.

«Загрузить папку токенов»: сначала остановите реле, укажите имя профиля,
выберите папку одного профиля (или его auth) с файлами *-cache.json.
Принимается полный кэш Live из этого реле/совместимого prismarine-auth.
Одиночный access token, cookies браузера и кэши другого формата не подходят.
Имена файлов кэша подстраиваются под выбранный профиль; содержимое токенов
не меняется. Для существующего профиля приложение запросит подтверждение:
старый auth останется в auth-backup-ДАТА рядом, новый кэш устанавливается
только после проверки и записи всех файлов. Загруженный профиль выбирается
для следующего запуска. Пустые JSON-заглушки от неудачного входа пропускаются;
несколько непустых аккаунтов в одной папке по-прежнему не смешиваются.
Если раньше вы копировали файлы вручную, загрузите эту же папку кнопкой:
простое копирование не исправляет ключ в именах файлов под выбранный ник.
Надпись «кэш найден» означает наличие файла, а не проверенную авторизацию.

«Сохранить папку…»: выберите место, где будет создана новая папка с именем
профиля. Это переносимая копия токенов; программа не загружает её в облако.
Не передавайте её другим, в ней содержится доступ к аккаунту. Новые папки
доступны только вашему пользователю Windows и SYSTEM; сам формат кэша
не зашифрован, чтобы сохранить совместимость. После переноса между ПК
права доступа могут отличаться. Истёкшие/отозванные токены потребуют
повторного входа Microsoft. Успешный вход с настоящими токенами здесь
не проверялся: тест импорта использует только искусственные данные.

ВЕРСИИ
В списке есть 1.21.2 и 1.21.100. Реле не является переводчиком версий:
выбранная версия должна совпадать с вашей игрой, а сервер её поддерживать.
Поддержка соединения не означает поддержку всех модулей на любой версии.
Для 1.21.2 и 1.21.100 используются отдельные форматы инвентаря,
клика по сундуку, обновления слота и запроса переноса. Идентификаторы
контейнеров сверены с SDK ПК DLL и схемами обеих версий. ID шалкеров
берутся из реестра текущего сервера, а ID открытого окна — из его пакета.
Неизвестный формат блокирует авторазгрузку. Разбор вложенного NBT сундука
не требуется: содержимое пропускается по длине и не сохраняется в кэше.
Вход в реальный Minecraft/сервер в этой Windows-сборке не проверен.

NBT
До запуска выберите свою папку в «Библиотека NBT» или импортируйте файл.
Поддерживаются файлы ПК QZNBTF02 (.qznbt) и .cpenbt.json.
Обычная структура Minecraft .nbt — другой формат, это не файл шалкера.
Выберите файл и нажмите «Включить NBT-крафт». Крафтите шалкеры вручную
в верстаке. Режим действует непрерывно до выключения.
В 1.0.2 исправлено получение результата через промежуточный слот интерфейса
(PlayerUIOnly/курсор), как в ПК DLL, на 1.21.2 и 1.21.100. Прямое получение
в инвентарь сохранено. Данные добавляются только к паре действий одного
результата крафта с совпадающими предметом, вариантом и количеством.
В журнале успешного переноса видно destinationWindow=ui или inventory.
«Сохранить из руки» записывает шалкер в указанный слот как .cpenbt.json.
Команды: .nbt copy, .nbt save имя, .nbt craft имя, .nbt off.
Имена: 1–32 английские буквы, цифры, _ или -.
Два разных формата не должны иметь одно имя слота: при импорте приложение
выбирает свободное имя, если другой формат с этим именем уже существует.
Ограничения исходного реле сохранены; NBT-режим ограничен портами
назначения 19132/19133. Сервер может отклонять изменённые предметы.

МОДУЛИ
Авторазгрузка переносит шалкеры в свободные ячейки открытого сундука.
Хотбар включается отдельно. Скорость: пауза 30–3000 мс; для тяжёлых NBT
начните с 1000 мс. Подтверждения сервера могут замедлять перенос.
Ручное перемещение/серверная коррекция могут приостановить разгрузку;
переоткройте сундук. Кнопка поверх Minecraft остаётся в сундуках и
перемещается за верхнюю полоску. Панель остаётся поверх окон при сворачивании
главного окна; проверка имени процесса Minecraft больше не скрывает её.
Показаны фактический статус ядра, количество отправленных и подтверждённых
переносов. В legacy-режиме сервер может не присылать подтверждения — счётчик
«Подтверждено» тогда не растёт, это не счётчик отправок.
Используйте оконный/безрамочный режим: обычная Windows-панель не гарантирует
отображение поверх эксклюзивного полноэкранного режима. Отключить её можно
в «Модули». Пока включена, она видна и поверх других приложений.
Автоброня и автототем используют тот же код, что Android-приложение.
Миникарта, ESP/визуальные схемы и Android-оверлей в эту первую Windows
версию не перенесены. Папка в библиотеке предназначена для NBT шалкеров.

ЕСЛИ MINECRAFT UWP НЕ ВИДИТ ЛОКАЛЬНОЕ РЕЛЕ
Проверьте, что реле запущено и порт 19132 не занят другим приложением.
У UWP-приложений Windows может быть запрещено подключение к localhost.
Опционально, только для вашей установленной UWP-версии Minecraft:
в PowerShell найдите точное семейство пакета:
  Get-AppxPackage *Minecraft* | Select-Object Name, PackageFamilyName
Затем в PowerShell от администратора добавьте исключение для выбранного
семейства (замените PACKAGE_FAMILY_NAME на найденное значение):
  CheckNetIsolation.exe LoopbackExempt -a -n="PACKAGE_FAMILY_NAME"
Чтобы отменить это исключение, используйте -d вместо -a.
Программа сама не меняет исключения, брандмауэр или настройки безопасности.
Документация Microsoft:
https://learn.microsoft.com/en-us/windows/uwp/communication/interprocess-communication

ДАННЫЕ И ПАМЯТЬ
Настройки, журнал, стандартная папка NBT и авторизация находятся в
%LOCALAPPDATA%\CPE Relay Windows. Не передавайте другим папки profiles/auth.
Тяжёлые операции выполняются вне потока интерфейса. Опрос состояния
не накапливает очередь; экран журнала и файлы журнала ограничены.
Это не подтверждённое исправление ранее наблюдавшейся утечки на Android.
Для журнала включайте «Подробный журнал» только при диагностике.

СБОРКА ИЗ ИСХОДНИКОВ
Нужны Windows x64, .NET SDK 8 и MSYS2 UCRT64 с GCC, CMake, Ninja,
OpenSSL и zlib. В репозитории должны присутствовать data/minecraft-data
и third_party/raknet — они входят в этот репозиторий.
Из корня репозитория запустите PowerShell:
  .\windows\relay-app\build.ps1 -Toolchain C:\msys64\ucrt64
Результат: windows/relay-app/dist/CPE-Relay-Windows-1.0.2-x64.exe.
Скрипт собирает общее ядро с оптимизацией и автономный .NET-интерфейс;
изменения DLL автоматически попадают внутрь EXE. -SkipNative используйте
только если native-ядро уже пересобрано отдельно.

Локальная проверка без входа в аккаунт (папка результата должна быть новой):
  .\windows\relay-app\dist\CPE-Relay-Windows-1.0.2-x64.exe --self-test C:\Temp\cpe-check-01

В указанной папке появятся result.json и изображения пяти экранов.
Проверяются профили на искусственных токенах, локальный запуск/остановка
и RakNet ping. Дополнительным аргументом можно передать свой .qznbt для
проверки импорта. Проверка не заменяет подключение Minecraft к серверу.
--shutdown-only исключает проверки порта 19132, но проверяет зависшую
операцию, кнопку остановки, закрытие окна, перезапуск и освобождение порта
дочернего процесса. Импорт проверяется на искусственных токенах с резервной
копией. tools/shulker_deposit_smoke.cpp проверяет оба формата переноса,
идентификаторы, подтверждения, 30 мс и большие непрозрачные NBT сундуков.

Проверка NBT-крафта без запуска реле и без подключения к серверу:
  cmake --build build-windows-app --target relay-nbt-craft-smoke
  .\build-windows-app\relay-nbt-craft-smoke.exe
Для отдельного тестового EXE нужны DLL MSYS2 UCRT64 в PATH.

Документация упаковки .NET:
https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview
