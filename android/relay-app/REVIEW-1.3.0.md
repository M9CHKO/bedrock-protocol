# Аудит CPE Relay 1.3.0

## Что следует из присланных логов

Старый выход процесса `reason=anr`, `Input dispatching timed out`, 10001 мс
означает зависание обработки ввода, а не доказанную нехватку памяти. Стек
заблокированного потока в присланном тексте отсутствует. Устранены найденные
блокирующие пути UI и источники нагрузки; многочасовой тест на телефоне
остаётся необходимым.

При неуспешном локальном входе есть `request_network_settings` и отправка
`network_settings`, но нет декодированного `login`. Счётчики показывают
`actualReceived=710825`, `userIgnored=695952`, `userReceived=225`. Следовательно,
это не отсутствие Minecraft и не ошибка OAuth к серверу назначения: данные
приходят, но не доходят до декодирования Login. Сам по себе общий счётчик
не объясняет конкретную причину отбрасывания.

Сравнение истории выявило более позднюю специальную ресинхронизацию окна
номеров датаграмм. Она отменена по запросу пользователя, но её причинная
связь с данным сбоем не доказана: `userIgnored` учитывает отбрасывание
сообщений в ReliabilityLayer, а отказ `OnGotPacket` находится раньше.
Поэтому watchdog дополнен metadata-only `reliability={...}`: число входящих
фреймов/фрагментов, последние reliable/order/split номера, число уведомлений
и последняя причина. Обычные дубликаты тоже учитываются; их наличие отдельно
от зависшего Login не является ошибкой.

## Исправления и ограничения

| Область | Изменение | Граница проверки |
| --- | --- | --- |
| Android UI | Три вкладки, общая палитра, доступные кнопки, отдельные состояния входа | Headless layout-тесты портрет/ландшафт; не скриншот реального телефона |
| UI/диск | Фоновое чтение состояния, журнала и запись логов с ограничением очереди; нативный stop вне main | Тесты очереди, ротации, очистки и редактирования секретов |
| Подсветка | Фоновая публикация autofill, отсечение рёбер AABB у near plane, повторное использование массивов | Геометрия тестируется; настоящая матрица камеры Minecraft по протоколу недоступна |
| Путь | Проверка промежуточных опор, 0.6×1.8 AABB, текущий yaw, реальные координаты начала | Чистые геометрические тесты; сервер может ограничить синтетическое движение |
| Установка | Грань опоры в пределах 3 блоков, видимость, ожидание обновления мира | Нет live-подтверждения на пользовательском сервере; расход предмета не считается доказательством установки |
| Чанки | Лимиты байтов и записей, отказ от копирования oversized packet | Тесты маленьких пакетов, замены, выселения, reset и payload-only |
| Транспорт | Возврат окна первой версии, исправление callback-close гонки, bounded receive diagnostics | Настоящий UDP smoke-тест с фрагментацией; Android/Minecraft требуют отдельного прогона |

Поддержки/запасные колонны, X/Y/Z-сдвиг области, пропуск занятых клеток и
восемь вариантов пополнения хотбара из предыдущей версии сохранены.
Не добавлялись разрушение существующих блоков, полёт над пустотой, движение
через неизвестные чанки или игнорирование серверной коррекции. Если цель
невозможна в этих условиях, автоматика должна сообщить об ожидании/остановке,
а не считать её построенной. Старый способ текстурных фантомов схем сохранён.

## Проверка на телефоне

1. Установить APK поверх предыдущей версии. Очистить старый журнал. Десять
   раз выйти из мира и подключиться к **локальному** реле, не перезапуская его.
   Если Login зависнет, сохранить новый watchdog с полем `reliability`.
2. Автозаливка 2×2 и полигон с последними дальними клетками: смотреть вбок
   во время прохода, проверить предел 3 блока, занятые клетки и отсутствие
   ложного завершения после отклонённой установки.
3. Проверить край, отверстие, низкий потолок, полублоки и незагруженный чанк.
   Опасный маршрут должен останавливаться; только серверный блок — опора.
4. Израсходовать хотбар при наличии того же блока в основном инвентаре.
   Проверить подтверждение переноса; при полном отсутствии блоков ходьба
   останавливается до нового ручного запуска.
5. Оставить подсветку включённой в неподвижной сцене, затем двигаться между
   чанками, выключить/включить её, переподключиться. Проверить отзывчивость
   меню, память, отсутствие накопления фигур и ограничение журнала.

## Источники и направление дальнейшего развития

Использованы исходники первой Android-версии, текущие протокольные схемы,
ветка [weathertop_bot dev](https://github.com/boredfedya/weathertop_bot/tree/dev)
для сверки осей ввода, документация Android по
[ANR](https://developer.android.com/topic/performance/views/vitals/anr-views),
[edge-to-edge](https://developer.android.com/develop/ui/views/layout/edge-to-edge)
и [Robolectric](https://robolectric.org/getting-started/).

Самый большой оставшийся архитектурный долг — `native_bridge.cpp`: логика
протокольного инвентаря, построения, мира и JNI тесно связана. В этой версии
чистая геометрия вынесена в `AreaFillGeometry.hpp`, UI-палитра — в `RelayUi`.
Перенос всего моста в новые классы без end-to-end стенда увеличил бы риск
регрессий; следующий полезный шаг — воспроизводимый серверный стенд для
подтверждений инвентаря/установки и отдельный измеряемый тест длительной сессии.
